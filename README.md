# Солнечная система в 3D

Интерактивная 3D-визуализация Солнечной системы на чистых `HTML`, `CSS` и `JavaScript` без сторонних библиотек и сборщиков. Сцена рисуется на `<canvas>` в реальном времени с перспективной проекцией, управлением камерой и эффектами столкновений.

## Возможности

- **8 планет на индивидуальных орбитах** — каждая планета имеет свои параметры: размер, цвет, наклон орбиты (`inclination`), угол восходящего узла (`node`), угловую скорость и начальную фазу.
- **Кольца Сатурна** — нарисованы отдельной эллипсовидной дугой.
- **Звёздный фон** — 180 звёзд с независимым мерцанием (фазовый сдвиг на каждую звезду).
- **Управление камерой**: поворот сцены перетаскиванием мыши, приближение/отдаление колесом.
- **Подпись при наведении** — всплывающий тултип с именем тела появляется при наведении на планету или на карточку легенды. Оба источника синхронизированы.
- **Система астероидов**: клик по планете или по карточке слева запускает астероид. Повторный клик восстанавливает планету.
- **Визуальные эффекты удара**: полёт с хвостом, прицел на цели, оранжевая вспышка при ударе, зелёная при восстановлении, планета окрашивается в красный.
- **Пауза / Сброс** — стандартные кнопки управления анимацией.
- **Ползунок скорости** — диапазон 0.2× — 3×.
- **Статус-строка** — отображает количество планет, текущую скорость, зум и углы камеры.
- **Адаптивная вёрстка** — при ширине < 980 px панель управления уходит наверх, при < 720 px уменьшаются отступы.
- **Доступность** — карточки легенды фокусируемы с клавиатуры (Tab), активируются Enter и Пробелом.

## Структура проекта

```
index.html   — разметка страницы: шапка, панель управления, холст, легенда
style.css    — оформление всех компонентов интерфейса, адаптивность
script.js    — вся логика: математика проекции, анимация, эффекты, события
```

### Архитектура script.js

Файл разбит на логические секции в таком порядке:

| Секция | Что делает |
|--------|-----------|
| Константы | Параметры проекции, камеры, цвета эффектов |
| Данные сцены | Описание Солнца и планет |
| Состояние (`state`) | Единый мутируемый объект для всей сцены |
| Утилиты | `toRadians`, `lerp`, `hexToRgba` и пр. |
| Орбитальная геометрия | Вычисление и кеширование точек орбиты |
| Камера и проекция | `buildCamera`, `projectPoint`, `projectSphere` |
| Обновление состояния | Позиции планет, продвижение эффектов |
| Логика астероидов | Запуск, прогресс, попадание, восстановление |
| Рендер | Фон, орбиты, тела, эффекты, подпись |
| UI и события | Легенда, холст, слайдер, кнопки |
| Главный цикл | `animate` → `requestAnimationFrame` |

## Как запустить

1. Откройте `index.html` в браузере — никаких зависимостей и сборки не требуется.
2. Если браузер показывает устаревшую версию после изменений в файлах, нажмите **Ctrl+Shift+R** (жёсткое обновление страницы).

## Техническое устройство

### 3D-проекция

Система использует ручную перспективную проекцию без WebGL.

**Координатная система** — правосторонняя: ось X вправо, Y вверх, Z на зрителя. Солнце находится в точке (0, 0, 0).

**Два поворота камеры:**
1. Поворот вокруг Y (`rotateYDeg`) — горизонтальное вращение мышью.
2. Поворот вокруг X (`rotateXDeg`) — вертикальный наклон; ограничен диапазоном −85°…+20°, чтобы не перевернуть сцену.

**Перспективное деление:**
```
perspective = FOCAL_LENGTH / (cameraDistance - rz)
screenX = width/2  + rx * perspective * sceneScale
screenY = height/2 - ry * perspective * sceneScale
```
`rz` (глубина точки после поворота) определяет масштаб: объекты ближе к камере выглядят крупнее.

**Радиус сферы на экране** зависит только от `rz`-компоненты её центра — это корректная аппроксимация для сферы при перспективной камере.

### Орбитальная геометрия

Каждая орбита — эллипс с большой полуосью `orbitA` и малой `orbitB`.

Алгоритм `computeOrbitPoint(planet, angle)`:
1. Строим точку в локальной плоскости орбиты: `localX = orbitA·cos(angle)`, `localZ = orbitB·sin(angle)`.
2. Поворачиваем на угол восходящего узла (`node`) вокруг Y — определяет, в каком направлении в плоскости эклиптики «разворачивается» орбита.
3. Поворачиваем на угол наклона (`inclination`) вокруг новой X — наклоняет плоскость орбиты к эклиптике.

Геометрия орбит статична, поэтому при инициализации строится кеш из 144 точек (`buildOrbitPoints`). Каждый кадр точки только проецируются — геометрия не пересчитывается.

### Сортировка тел

`buildBodies()` возвращает один массив. Из него делаются два экземпляра:
- **`hitTestBodies`** — отсортирован сзади наперёд (от большего `depth` к меньшему). Первое совпадение при hit-test — ближайшее к зрителю тело.
- **`projectedBodies`** — отсортирован спереди назад (painter's algorithm). Тела рисуются в этом порядке, ближние перекрывают дальние.

### Оптимизации производительности

| Проблема | Решение |
|----------|---------|
| `getBoundingClientRect()` вызывался дважды за кадр (reflow) | Один вызов в `drawScene()`, результат передаётся в `resizeCanvasToDisplaySize(rect)` |
| `createRadialGradient()` создавался каждый кадр | Кеш объекта градиента, инвалидируется только при изменении размера холста |
| `hexToRgba()` парсил одни и те же строки на каждом кадре | Мемоизация через `Map`; после первого кадра — только поиск по ключу |
| `getBoundingClientRect()` на каждый `mousemove` (drag) | Кеш в `getCanvasCoordinates()`, сбрасывается при `resize` |
| `textContent` статус-строки обновлялся 60 раз/с | Троттлинг ≤10 раз/с + пропуск если строка не изменилась |

### Система легенды

Легенда работает через делегирование событий: слушатели прикреплены к родительскому `<ul>`, а не к каждому `<li>` отдельно. Внутри обработчика `event.target.closest(".planet-legend__item")` ищет нужный элемент. Элементы хранятся в `Map<key, li>` для мгновенного обновления классов в `syncLegendState()` без обхода DOM.

Состояния карточки:
- `.is-active` — тело сейчас под курсором или в фокусе.
- `.is-damaged` — планета поражена астероидом.
